# 第一阶段完成清单

> 依据 `docs/REQUIREMENTS.md` 原文整理（括号内为原文出处）。每完成一步更新打勾，并注明对应的提交或文件。

## 一、功能（初始用户需求）

### 1. 用户账号（需求一）
- [x] 注册账号（用户名、密码、注册时间）（第三步）
- [x] 登录账号（JWT，第三步）
- [x] 使用自己的账号创建问卷（第四步）
- [x] 查看自己创建的问卷（第四步）
- [x] 查看问卷的统计结果（第八步）
- [x] 登录后只能看到自己创建的问卷（他人的问卷、统计、答卷均返回 404）

### 2. 问卷创建与管理（需求二）
- [x] 创建问卷：标题、说明、是否允许匿名填写（另含本项目的提交策略设置）
- [x] 查看自己创建的问卷列表（含题目数、答卷数）
- [x] 发布问卷
- [x] 设置问卷截止时间（创建时或之后修改；过期后可延长）
- [x] 关闭问卷
- [x] 每个问卷有可访问的链接 `/survey/xxxxxx`（前缀由 `PUBLIC_BASE_URL` 配置）
- [x] 填写问卷的人需要先登录（第七步，填写接口均需登录）

### 3. 题目（需求三）
- [x] 一个问卷可包含多个题目（第五步：添加、修改、删除、调整顺序）
- [x] 单选题：设置选项、是否必答；必答时填写必须选择
- [x] 多选题：至少选 N 个、最多选 N 个、必须选 N 个；填写时检查
- [x] 文本填空：最少/最多字数；填写时检查
- [x] 数字填空：最小值、最大值、是否必须为整数；填写时检查（如年龄 0~120 整数、手机号整数）
- [x] 整数答案超出 64 位范围时按校验错误提示（设计文档 6.6）

### 4. 题目跳转（需求四）
- [x] 根据单选结果跳转
- [x] 根据多选结果跳转
- [x] 根据数字填空内容跳转
- [x] 填写时自动跳到对应题目（9c 滚动式填写页：由路径预览接口逐题展开）
- [x] 跳转规则在问卷中设置，不写死在程序里（规则存在题目的 logic 中；运算符表 `app/logic/operators.py`；保存时整体检查，第五步）

### 5. 填写问卷（需求五）
- [x] 通过问卷链接进入问卷（未登录先跳转登录，登录后自动回到问卷）
- [x] 按顺序回答问题（路径预览逐题返回下一题）
- [x] 根据规则跳转（提交时后端重算路径）
- [x] 填写不符合要求时提示错误（预览返回 errors；提交返回 422）
- [x] 填写完成后提交
- [x] 每次填写都被保存（只改 isLatest，不删除；失败的提交不保存）
- [x] 支持多人同时填写（10 人并发测试；同一人并发提交由索引与撤销保证）
- [x] 支持匿名填写（记录但不展示：匿名问卷的统计和答卷列表管道不含 $lookup、不输出 respondentId）
- [x] 支持同一个人填写多次（如果允许）（once / latest / all 三种策略）

### 6. 统计结果（需求六）
- [x] 单选题：每个选项多少人选择、总共多少人回答（同时返回答卷数和去重后的作答人数，设计文档 6.7）
- [x] 多选题：每个选项被选择多少次
- [x] 填空题：查看所有填写内容（整份统计列最新 20 条；单题统计分页查看全部）
- [x] 数字填空：平均值
- [x] 查看整个问卷的统计
- [x] 查看某一道题的统计
- [x] 统计根据已填写的数据自动生成（聚合管道实时计算，设计文档 6.8）

## 二、技术与 MongoDB 设计（项目说明三、四）
- [x] 后端数据库为 MongoDB，所有数据存储在 MongoDB 中（第二步 `ea5b299`）
- [x] 不使用关系数据库
- [ ] 不使用现成问卷系统框架（全程遵守，最终检查依赖列表）
- [x] 不把所有数据存在一个集合（users / surveys / responses）
- [x] 谨慎使用冗余设计（设计文档 7.5）
- [x] 逻辑不写死在代码中（校验、跳转规则存为题目数据；程序只解释：运算符表与判断函数 `app/logic/operators.py`、校验 `app/logic/validation.py`、路径 `app/logic/jump.py`）
- [x] 说明为什么这样设计（设计文档第七节）
- [x] 说明为什么不用关系数据库结构、为什么适合 MongoDB（设计文档第八节）
- [x] MongoDB schema：`$jsonSchema` 校验和索引脚本（`app/db_schema.py`、`scripts/init_db.py`）
