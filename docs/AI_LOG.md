### 4. 数据库设计讨论：跳转规则（2026-10-19）
- 工具：Claude（claude.ai）
- 提示词：“跳转规则比如呢？我们来讨论一下”及后续逐条讨论
- AI 产出：规则结构 `{when: {op, value}, goto}` + `defaultNext`；各题型运算符候选；冲突处理、往前跳、结束、选填未答、被跳过题目的处理建议。
- 是否修改：
- 修改内容 / 本人决定：
  - 单选采用 `eq` + `in`；多选采用 `contains / containsAny / containsAll / equals`，不做 `countGte`；数字采用全部 7 个运算符；文本不支持跳转。
  - 本人质疑“多条规则同时满足是否因为限制不够严格”，讨论后明确：单选/数字题的重叠属于设置错误，可检查；多选题重叠不可避免，需要“第一条命中为准”兜底，可通过把 `containsAll` 规则放前面处理“都选了”的情况。
  - 确认只能往后跳；路径外的多余答案选择“丢弃”而不是“拒绝提交”。

### 7. 编码前审阅设计、确认技术栈与实施计划（2026-10-19）
- 工具：Claude Code
- 提示词：要求 Claude Code 先完整阅读 `CLAUDE.md`、`docs/DATABASE_DESIGN.md`、`docs/AI_LOG.md`，暂不写业务代码：复述对项目的理解；确认技术栈和需要安装的环境；列出 6.5 节待确认事项及阅读设计时发现的问题，逐条询问；给出目录结构、API 草案、分步计划和测试方案。
- AI 产出：
  - 检查本机环境：Python 3.14.2、MongoDB 8.3.11（未注册为服务）、mongosh 2.12、Git 2.53；项目尚未初始化 git 仓库。
  - 建议密码哈希直接使用 `bcrypt` 库代替已停止维护的 `passlib`。
  - 给出目录结构（`logic/` 存放校验、跳转等纯函数模块）、API 列表草案、11 步实施计划、测试方案（单元测试 + 接口集成测试，独立测试库 `survey_test`）。
  - 阅读设计时**由 AI 发现并提出**的问题（共 14 条，第 5~18 条）：设计文件实际放在根目录而非 `docs/`；单机 MongoDB 无事务，“先把旧答卷置 false 再插入新答卷”若中途失败会导致没有最新答卷；两个索引键相同（普通索引与部分唯一索引）；整份提交题目数组时新题没有 id、跳转规则无法引用；id 生成方式未定义；发布后哪些设置可改未定义；“总作答人数”口径不明确；文本字数、数字类型、空答案等校验细节未定义；发布条件；问卷能否删除；创建者能否填写/预览；“查看答卷”接口是否需要；前端跳转逻辑是否与后端重复实现；`$jsonSchema` 校验严格程度可能妨碍第二阶段加字段。
  - 按开发者决定创建 `docs/` 目录并移入设计文件；同步更新 `docs/DATABASE_DESIGN.md`（3.1、第 5 节、5.1、6.1~6.7、修订记录）。

- 修改内容 / 本人决定：
  - 技术栈采用默认方案，同意用 `bcrypt` 库代替 `passlib`。
  - 6.5 节四项待确认事项全部采用默认做法。
  - 写入顺序：同意 AI 提出的三步写入顺序（latest/all）；**本人补充**：`once` 策略直接插入 `isLatest: true`，靠部分唯一索引拦截重复提交。
  - 索引：**本人决定**只保留部分唯一索引，删除普通索引，判断是否填过时查询带 `isLatest: true`。
  - 同意单题接口 + 每次修改后整体检查；同意 id 格式 `q_`/`o_` + 6 位随机字符。
  - 发布后可改项：**本人决定**允许修改标题、说明、截止时间（只能改到当前时间之后）；匿名设置和提交策略锁定，理由是会影响已收集答卷的统计口径和隐私承诺。（AI 原建议只允许延长截止时间。）
  - 同意“总作答人数”口径、校验细节、发布条件、只能删除草稿、创建者可填写自己的问卷。
  - 同意增加只读答卷列表接口；**本人决定**非匿名问卷的填空题统计附带填写人用户名，匿名问卷不附带。
  - 同意路径预览接口，提交时后端仍完整重算路径；同意 `$jsonSchema` 宽松校验策略。
